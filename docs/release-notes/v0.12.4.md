# v0.12.4 — 運用・品質・セキュリティ強化（CI E2E / 監視通知 / コネクタ / AI / PDF / 非同期検索 / SSO）

日付: 2026-08-31

## 主な変更

### CI と監視（#12・#10）
- CI に `e2e` ジョブを追加: postgres:17 サービス → `scripts/migrate.mjs` → API 起動 → `smoke-e2e.mjs`（主要業務フロー）＋ `smoke-local.sh`
  - Neon ブランチや Actions Secrets に依存しない（#39 のブロックを回避）
- ヘルスチェック失敗時に Slack 互換 Webhook へ通知（`ICRPS_ALERT_WEBHOOK_URL`）
  - `ICRPS_SKIP_RESTART=1` で試験可能・CI で通知経路を自動検証

### 検索コネクタの堅牢化（#4・#3）
- Google Patents / DuckDuckGo / SerpAPI の HTML スナップショットテストを追加し、構造変更を CI で検知
- robots.txt 遵守・レート制限（1検索1リクエスト＋リトライ1回）・失敗時は failureSources で他ソース継続する方針を明文化

### AI 品質（#5）
- `validateJsonOutput`: required に加えて型・配列要素・ネスト（evidence 等）を検証
- JSON パース・検証・空応答の失敗時のみ 1 回リトライ（API エラーは再試行しない）
- `llm_usage.duration_ms` を追加（migration 0011・additive）し実行時間を記録
- `docs/prompts.md` を新設（プロンプト・モデル・検証・記録方針）

### PDF 本文抽出（#6）
- 手動登録フォームで pdfjs-dist により本文抽出（20MB / 先頭30ページ / 30万文字制限）
- ライセンス確認必須（未確認時はメタデータのみ・サーバーも fail closed）

### 検索パイプラインの非同期化（#2）
- `POST /api/search` が 202 + `queued` を即時返却（実測 13ms）
- `queued → running → completed/failed` を `search_queries` に永続化
- 実行方式: Cloudflare Queues（任意）→ `executionCtx.waitUntil` → Node タイマー

### 認証基盤（#1）
- Microsoft Entra ID（Azure AD v2）SSO を実装（Google SSO と共通化）
- `docs/design/auth.md` に認証フロー・レート制限・監査・タイミング対策・TOTP MFA 設計を整備
