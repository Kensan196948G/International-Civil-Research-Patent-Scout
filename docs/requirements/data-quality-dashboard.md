# 収集データ品質ダッシュボード要件定義

ステータス: 要件定義（実装未着手） / 対象バージョン: v0.11 以降

## 1. 目的

文献収集（J-STAGE / 土木研究所 / ITC / 国交省 / 関東地整）と横断検索で蓄積される
`source_documents` の品質を定量的に監視し、欠損・重複・古いデータ・取得失敗を早期に検知する。

## 2. 指標（必須）

| 指標 | 定義 | 閾値（初期案） |
| --- | --- | --- |
| 欠損率（要旨） | 要旨（abstract）が NULL の文書割合 | 警告 30% / 重大 50% |
| 欠損率（著者） | 論文・特許で著者/発明者/出願人が NULL の割合 | 警告 40% |
| 重複率 | 同一 DOI/特許番号/URL の重複行割合（部分ユニークを超える検出） | 警告 1% |
| 更新日欠損 | publication_date が NULL の割合 | 警告 30% |
| 古さ（freshness） | 直近 5 年以内の割合 | 目標 60% |
| 取得失敗率 | ingest.run の status=error 割合（7日/30日） | 警告 5% / 重大 20% |
| 情報源別の件数推移 | 日次新規・スキップ件数 | 急減・ゼロを検知 |
| リンク有効率 | 保存 URL のサンプル HTTP ステータス（別途バッチ） | 警告 95% 未満 |

## 3. 画面（管理 /admin に追加）

- サマリーカード: 総文書数・欠損率・重複率・取得失敗率・直近収集時刻
- 情報源別テーブル: 件数・新規/スキップ・失敗・最終成功
- トレンド: 過去 30/90 日の指標推移
- 異常アラート: 閾値超過を監査ログと管理者メールへ

## 4. API

- `GET /api/admin/data-quality?days=30`（admin のみ）
- レスポンス: `{ summary, bySource[], trend[], alerts[] }`
- 日次集計ジョブ: `icrps-daily.service` に組み込み、結果を `audit_logs`（action=`data_quality.run`）へ記録

## 5. 受け入れ条件

- 日次集計が失敗せず、30日分のトレンドを保持
- 閾値超過で管理者メール（RESEND 設定時）と監査ログに記録
- 集計 SQL はパラメータ化・インデックス利用
- テスト: 集計ロジックの単体、API の権限・異常系
