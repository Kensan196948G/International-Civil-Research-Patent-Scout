# 特許コネクタ要件定義（J-PlatPat / PATENTSCOPE / 手動取り込み）

ステータス: 要件定義（実装未着手） / 対象バージョン: v0.11 以降

## 1. 目的

現在の特許検索は Google Patents（HTML パースまたは SerpAPI）と Espacenet OPS（任意）のみ。
日本の公共調達・国内特許調査では J-PlatPat、国際調査では PATENTSCOPE が一次情報として重要であり、
これらを「自動取得は行わず、手動取り込み UI とリンク検証」で補完する。

## 2. 対象ソースと方針

| ソース | 種別 | 方針 | 理由 |
| --- | --- | --- | --- |
| J-PlatPat | 国内特許・実用新案 | 手動取り込み UI + 公開番号リンク検証 | 認証・利用規約・レート制限のため自動取得しない |
| PATENTSCOPE | 国際特許（PCT 等） | 手動取り込み UI + 公開番号リンク検証 | 利用規約・API 契約の確認が必要 |
| Espacenet OPS | 国際特許 | 自動検索（キー設定時） | 公式 API。キー未設定時はスキップ |
| Google Patents | 国際特許 | 現行 HTML パースを維持（失敗時は公式/SerpAPI へ切替） | 無料だがページ変更に弱い |

## 2.1 Google Patents HTML パースの運用方針（#4）

- **robots.txt 遵守**: 検索はユーザー操作（`POST /api/search`）に起因する 1 検索 1 リクエストのみ。
  バックグラウンドでの巡回・一括取得・スクリーンスクレイピングは行わない。
  `User-Agent` は `CivilResearchPatentScout/0.1` を名乗り、問い合わせ先を設定する。
- **レート制限**: 1 検索あたり最大 1 リクエスト＋失敗時 1 リトライ（500ms バックオフ）。
  明示的な間引きやページング自動取得は行わない。結果は DB（source_documents）に保存され、
  同一クエリの再検索時も外部へ無制限に再リクエストしない。
- **構造変更の自動検知**: `apps/api/test/patent-connectors.test.ts` に現在の結果一覧 HTML と
  フォールバック（スニペット）HTML のスナップショットテストを保持する。ページ構造変更で
  パース結果が変化した場合は CI が失敗し、検知・修正のきっかけとなる。
- **失敗時の挙動**: パース結果が 0 件でも検索は失敗させず、空配列＋`failureSources` 記録で
  他ソース（論文・Web）の検索を継続する。通信失敗は例外として pipeline 側で特許ソースのみスキップする。
- **代替経路**: SerpAPI（`SERP_API_KEY` 設定時）→ Espacenet OPS（キー設定時）の順に利用可能。

## 3. 手動取り込み UI（必須要件）

- 公開番号（例: JP2024-123456A / WO2024/123456A1）の入力と形式バリデーション
- タイトル・出願人・発明者・出願日・公開日・IPC/CPC・要約・URL の編集項目
- DOI 相当の重複キー（公開番号）による既存文献との突合
- プロジェクトへの同時保存
- 入力履歴の監査ログ（`document.import`）

## 4. リンク検証（必須要件）

- 保存時に公開番号から公式 URL を生成（J-PlatPat: `https://www.j-platpat.inpit.go.jp/...`、PATENTSCOPE: `https://patentscope.wipo.int/search/en/detail.jsf?docId=...`）
- 保存後は「出典」リンクとして表示し、原典確認を必須表記
- リンク検証の自動化は各サイトの利用条件を確認後に判断

## 5. 受け入れ条件

- 公開番号形式の誤りが 400 で返る（バリデーションテスト）
- 重複登録が発生しない（部分ユニークインデックス）
- 手動登録が監査ログに記録される
- 権限: editor 以上のみ登録可、viewer は閲覧のみ
- テスト: 正常系（国内/国際番号）、異常系（形式不正・重複・未認証・権限不足）

## 6. 非機能要件

- 利用規約・robots.txt・レート制限の遵守（自動取得は行わない）
- 個人・機密情報を扱わない（公開メタデータのみ）
- API キー・契約が必要な場合は env/Secret 管理と文書化
